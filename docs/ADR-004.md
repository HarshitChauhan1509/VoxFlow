# ADR 004: Tenant-Aware Repository Pattern

## Context
In a multi-tenant SaaS application, accidentally querying or updating data belonging to another tenant (IDOR) is a catastrophic security risk. Traditional ORM usage requires developers to manually append `where: { workspaceId }` to every query, which is error-prone.

## Decision
We implemented a `WorkspaceRepository` class that acts as a mandatory abstraction layer over Prisma. It is initialized with a `workspaceId` and automatically injects this condition into all underlying database queries (`findFirst`, `create`, `updateMany`).

## Consequences
- **Positive:** Systemic protection against IDOR vulnerabilities. Developers cannot query data outside the initialized workspace context.
- **Negative:** Adds a layer of indirection over Prisma's native API, requiring explicit implementation of repository methods for new entities.
