# ADR 005: Resilient Background Processing with BullMQ

## Context
Processing audio and analyzing text with AI involves network latency and provider unreliability. Synchronous API processing is impossible due to timeouts, and basic asynchronous execution without state machines leads to lost data or duplicated provider costs during crashes.

## Decision
We utilize BullMQ backed by Redis for durable, distributed task queues. We implemented:
1. Exponential backoff (3 attempts, 2000ms delay).
2. Idempotency checks inside worker handlers (e.g., verifying `job.status === 'COMPLETED'` before executing).
3. Graceful shutdown hooks (`SIGTERM` and `SIGINT`) using `worker.close()` to ensure in-flight jobs are safely returned to the queue or completed.

## Consequences
- **Positive:** Resilient to pod evictions and transient network errors. Prevents duplicate billing for AI API calls.
- **Negative:** Increased operational complexity requiring Redis and monitoring of delayed/failed queues.
