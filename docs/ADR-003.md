# ADR-003: Why SSE instead of WebSockets

## Status
Accepted

## Context
The application needs to push real-time job progress (Pending -> Processing -> Completed) to the client so that users do not need to manually refresh the page or suffer from inefficient HTTP polling.

## Decision
We will use Server-Sent Events (SSE) instead of WebSockets.

## Consequences
- **Advantages:**
  - SSE uses standard HTTP and is much simpler to implement, secure, and proxy than WebSockets.
  - Built-in reconnection support in browsers (`EventSource`).
  - Unidirectional flow (Server to Client) fits our use case perfectly, as the client only needs to receive status updates after initiating the job via a standard POST request.
- **Disadvantages:**
  - Limited to unidirectional communication (not an issue for this architecture).
  - Browser limitations on concurrent HTTP/1.1 connections (mitigated by modern HTTP/2 usage in production).
