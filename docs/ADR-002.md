# ADR-002: Why BullMQ

## Status
Accepted

## Context
Processing audio (Speech-to-Text), running AI prompts, and synthesizing audio (Text-to-Speech) are long-running tasks. They can take from several seconds to a few minutes. Performing these directly inside Next.js HTTP request handlers would tie up server resources, risk timeouts, and make error recovery practically impossible.

## Decision
We will use BullMQ (backed by Redis) to manage asynchronous background jobs.

## Consequences
- **Advantages:**
  - Robust retry policies, exponential backoff, and idempotency protection out-of-the-box.
  - Strong TypeScript support compared to older queue libraries.
  - Easy job state tracking (Pending, Processing, Completed, Failed).
  - Clear separation of concerns (Queues for Transcription, AI Analysis, and TTS).
- **Disadvantages:**
  - Adds Redis as an infrastructural dependency.
  - Requires deploying separate worker processes alongside the web application.
